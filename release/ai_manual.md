# のぞけるディスプレイ（peek_display）AI用マニュアル

## このファイルを読んだAIへ

このファイルは、アプリ「のぞけるディスプレイ」（peek_display.exe）を受け取った人が、操作で困ったときにAIへ渡すためのものです。あなたはこのアプリのサポート役として答えてください。

- 答えは、このファイルに書いてあることだけを根拠にする。書いていないことは推測で答えず、「このマニュアルには書いてない」と伝え、配布した人に聞くよう案内する
- 相手はプログラムに詳しくない人かもしれない。メニューの場所は「ファイル → 保存」のように、画面に出ている言葉で示す
- 相手がエラーの文を貼ってきたら、下の「困ったとき」から当てはまるものを探す
- アプリの中身（exe）やソースコードは相手の手元に無い。ソースを直す方法は案内しない

## アプリの概要

- 東北大学メタバース研究会が、2026年度 第78回 東北大学学園祭で展示するアプリ
- 見る人の頭にARマーカーを付ける（またはかざす）と、Webカメラと OpenTrack で頭の位置を測り、その位置から見た3D空間をディスプレイに映す。ディスプレイが「向こう側をのぞける窓」のように見える
- Windows 専用。OpenTrack（頭の位置を測る無料ソフト、2026.1.0 で確認）と Webカメラが要る
- 頭の位置は、OpenTrack から UDP（127.0.0.1 のポート 4242）で受け取る

## 配布フォルダの中身

| ファイル | 内容 |
|---|---|
| peek_display.exe | アプリ本体。ダブルクリックで起動する |
| scenes フォルダ | 保存したシーン（`.peek`）。current.txt は最後に開いたシーンの名前 |
| config.ini | このPCと設置場所の値（機材プロファイル）。初回起動時に自動で作られる |
| README.md | 使い方（このファイルの後半に同じ内容がある） |
| ARマーカー_test3.png | 印刷して使うARマーカー |
| OpenTrackのダウンロード.url / ARマーカーのダウンロード.url | ダウンロードページへのリンク |

- config.ini と scenes フォルダは、**起動したときの作業フォルダ**から読み書きする。exe をダブルクリックすれば exe と同じフォルダになる。ショートカットから起動するときは、ショートカットのプロパティの「作業フォルダー」を exe のフォルダにする
- 問題が起きると、画面の上の中央に「問題が起きました」と、その内容が出る（✕ で閉じる。文は選んでコピーできる）。アプリが異常終了したときは、理由がダイアログで出る（ダイアログで Ctrl+C を押すと内容をコピーできる）

## 困ったとき

### OpenTrack が起動しない
- 「問題が起きました」に「OpenTrack の起動に失敗しました」と出ていたら、config.ini の `opentrack_path` が OpenTrack の実行ファイルの場所と合っていない。初期値は `C:\Program Files (x86)\opentrack\opentrack.exe`。OpenTrack を入れていなければ、先にインストールする
- config.ini を書き換えたら、アプリを起動し直す

### トラッキングが始まらない（頭を動かしても映像が変わらない）
- アプリは起動の3秒後から、2秒おきに F12 キー（OpenTrack の開始キー）を押し、最大30秒待つ。だめなときは、「問題が起きました」に「OpenTrack のトラッキングを自動で開始できませんでした」と出る。タスクトレイの OpenTrack のアイコンから画面を開き、「Start」を押す
- マーカーがカメラに映っているか確かめる。config.ini の `minimize_opentrack=false` にして起動し直すと、OpenTrack の画面でカメラ映像を見られる
- 使うカメラは OpenTrack の画面で選ぶ（ノートPCの内蔵カメラと外付けカメラを取り違えやすい）
- 暗い場所、マーカーの反射、印刷がにじんでいるときは認識しにくい
- 「問題が起きました」に「UDP Socket のバインドに失敗しました (Port 4242)」と出ていたら、このアプリがもう1つ起動しているか、ほかのソフトがポート 4242 を使っている。ほかを閉じてから起動し直す

### カメラを開けない・OpenTrack が2つある
- アプリが異常終了すると、OpenTrack が残ったままになり、次の起動でカメラを取り合うことがある。タスクトレイやタスクマネージャーで OpenTrack を全部終了してから、アプリを起動し直す

### 見え方がずれる（近づいた・離れたときの動きが大きすぎる／小さすぎる）
- センター合わせ: 画面の正面、config.ini の `viewer_base_distance`（初期値 0.5m）の距離に頭を置いて、C キーを押す
- マーカーの大きさ: 黒い四角の一辺を定規で測り、編集モードの「スクリーン → 機材（このPC）→ トラッキング → マーカーの大きさ」に入れる（4cm 以外で印刷したとき）
- 画面の大きさ: 「スクリーン → 機材（このPC）」で、画面の対角インチか、定規で測った映る部分の幅（mm）を入れる
- カメラの視野角（初期値 56°）がカメラと合っていないと、距離がずれる。カメラの仕様の「対角の視野角」を入れる。保存すると OpenTrack が起動し直し、数秒トラッキングが止まる
- 変えた値は「ファイル → 保存」（Ctrl+S）で config.ini に書き込まれる

### C キーや F12 キーが効かない・勝手に何か起きる
- C（センター合わせ）と F12（トラッキング開始）は OpenTrack 用に予約されている
- アプリは起動のたびに OpenTrack のプロファイル（ドキュメント\opentrack-2.3\display.ini）に、トラッカー・出力・キー・視野角などを書き込み、OpenTrack が使うプロファイルを display に切り替えてから起動する。OpenTrack の画面でこれらやプロファイルを変えても、次の起動で元に戻る。カメラの選択は残る

### 編集モードのキー操作が効かない
- パネルで文字を入力している間は、キー操作は効かない。シーンビューをクリックしてから操作する
- 物を動かすキーは、オブジェクトかスクリーンを選んでいるときだけ効く

### 保存できない
- 配布フォルダを「Program Files」の中など、書き込めない場所に置いていると保存できない。デスクトップやドキュメントなどに置く
- 名前の無いシーンは上書き保存できない。「ファイル → 名前を付けて保存」（Ctrl+Shift+S）を使う

### モデルが読み込めない・表示されない
- 読み込めるのは .glb / .gltf だけ。FBX などは Blender で .glb に変換する
- .gltf が自分のフォルダの外のファイル（テクスチャなど）を参照していると、そのファイルは読み込まれない。.glb で書き出すのが確実
- Blender で書き出すときに「カメラ」「パンクチュアルライト」にチェックを入れないと、`peekScreen` カメラとライトが入らない

### 日本語が表示されない（文字が四角になる）
- Windows の日本語フォント（游ゴシック、メイリオ、MS ゴシックのどれか）を使う。どれも無いPCでは表示されない

### 画面を元に戻したい
- どのモードからも Esc でホーム画面に戻る
