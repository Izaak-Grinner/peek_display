## 1. 画面の実寸の計算を「変わったときだけ」にする

**対象**: `src/config/display.rs` の `update_display_info`（[解説 04](code/04_display.md)）

### 今の動き

`update_display_info` は `PreUpdate` に登録されていて、**毎フレーム** 次の計算をしています。

1. メインモニターの画素数を取る（取れなければウィンドウの画素数）
2. config.ini の値（対角 or 幅）と画素数から、画面の実寸(m)を出す
3. 前と違うときだけ `DisplayInfo` に書き込む

### 問題点

値が変わる場面は限られていて、それ以外のフレームでは毎回同じ結果を出しているだけです。

値が変わる場面:

| 場面 | 理由 |
|---|---|
| 起動直後の数フレーム | モニターの情報は起動直後にはまだ取れない。それまでは仮の値（1920×1080、16インチ）を使う |
| 編集モードで画面サイズの数値を変えたとき | ドラッグ中も、シーンビューの枠と右下の小窓がすぐ追いかける |
| 元に戻す（Ctrl+Z）で config の値が戻ったとき | |
| Windows の設定でモニターの解像度を変えたとき | |

> 起動直後はモニターの情報がまだ無いので、「起動時に1回だけ計算する」形にはできません。

### 変更案

「config が変わったとき」か「モニターの情報が変わったとき」だけ動く条件を付けます。

```rust
// src/config/display.rs の DisplayPlugin::build
impl Plugin for DisplayPlugin {
    fn build(&self, app: &mut App) {
        app.init_resource::<DisplayInfo>()
            .add_systems(
                PreUpdate,
                update_display_info.run_if(
                    resource_changed::<AppConfig>
                        .or(any_match_filter::<Changed<Monitor>>),
                ),
            );
    }
}
```

- `resource_changed::<AppConfig>` … config が変わったフレーム（編集、元に戻す、起動直後の1回目）
- `any_match_filter::<Changed<Monitor>>` … モニターの情報が増えた・変わったフレーム

`resource_changed::<SceneLayout>` は [scene.rs](code/11_scene.md) などで既に同じ形で使っています。

### 注意点

- **モニターの情報が取れないときの代わり（ウィンドウの画素数）が条件から漏れる**: その場合、ウィンドウの大きさを変えても再計算されません。対応するなら `.or(any_match_filter::<Changed<Window>>)` も足します（ただしウィンドウはマウスを動かすだけでも変更扱いになることがあり、結局ほぼ毎フレーム動く可能性があります）
- `any_match_filter` が Bevy 0.17 で使えるか、ビルドで確認が必要
- 変更後は Windows 実機で次を確認する
  - 起動直後に画面サイズが正しい値になるか（編集モード → スクリーン → 画面サイズ の「実寸」）
  - 編集モードで対角・幅の数値を変えると、シーンビューの枠がすぐ追いかけるか
  - Ctrl+Z で戻したときも追いかけるか

### 判断

| | |
|---|---|
| 速くなる分 | ほぼゼロ（毎フレームの処理は、モニター情報の読み取りと掛け算・割り算数回だけ。結果が同じなら書き込まないので、ほかの処理も動かない） |
| 壊れる危険 | 条件の漏れで、画面サイズが更新されない場面ができる |
| おすすめ | **今のままにする。** 処理の意図を分かりやすくしたい場合だけ直す |
