# 02 app_mode.rs　モードと画面の分割

**一言で**: ホーム／本番／検査／編集の4つのモードを管理し、モードごとに「どのカメラを画面のどこに描くか」を決める。
**場所**: `src/app_mode.rs`（142行）
**関係するファイル**: [07 main_camera](07_main_camera.md)、[08 scene_view](08_scene_view.md)、[04 display](04_display.md)、[23 edit_panel](23_edit_panel.md)

## 画面に出るカメラは2台

このアプリの3D画面は、2台のカメラの映像でできています。

| カメラ | 目印のシール | 映すもの |
|---|---|---|
| メインカメラ | `MainCamera` | 頭の位置に合わせた「窓の見え方」（本番の映像） |
| シーンビューカメラ | `SceneViewCamera` | 3D空間を外から見た映像（マウスで回せる） |

このファイルは、モードに応じて2台を **オン／オフ** し、**描く範囲（ビューポート）** を決めます。

```
ホーム          本番              検査                     編集
┌─────────┐   ┌─────────┐   ┌────────┬────────┐   ┌──────────────┐
│シーン   │   │メイン   │   │シーン  │ メイン │   │メニュー       │
│ビュー   │   │カメラ   │   │ビュー  │(比率   │   ├──────┬───────┤
│(全画面) │   │(全画面) │   │        │ 合わせ)│   │シーン │パネル │
│+ボタン  │   │         │   │        │        │   │ビュー │       │
└─────────┘   └─────────┘   └────────┴────────┘   └──────┴───────┘
```

## 出てくるデータ（型）

### `AppMode`（11〜21行目）

```rust
#[derive(States, Default, ...)]
pub enum AppMode {
    #[default]
    Home,        // 起動したらここから始まる
    Production,  // 本番
    Inspection,  // 検査
    Edit,        // 編集
}
```

- `#[derive(States)]` で Bevy の「ステート」になります。ほかのファイルで `in_state(AppMode::Edit)` のように「このモードのときだけ動く」と書けるようになります
- `#[default]` が付いた `Home` が起動時のモードです
- モードを変えるには `NextState<AppMode>` に `next.set(AppMode::Home)` のように書きます

### `EditViewInsets`（24〜30行目）

```rust
pub struct EditViewInsets {
    pub right: f32,  // 右側のパネルの幅
    pub top: f32,    // 上のメニューバーの高さ
}
```

編集モードでは、UI（メニューとパネル）が画面の一部を使います。
UI 側（[edit_panel.rs](23_edit_panel.md)）が毎フレームここに幅と高さを書き、このファイルがそれを避けてシーンビューを描きます。

## 関数ごとの説明

### `AppModePlugin::build`（34〜55行目）　登録

| 登録しているもの | いつ |
|---|---|
| `return_home_on_esc` | 毎フレーム。ただし **編集モードとホームでは動かない** |
| `update_camera_layout` | 毎フレーム |
| 全画面にする処理 | 本番モードに **入ったとき**（`OnEnter`） |
| ウィンドウに戻す処理 | 本番モードから **出たとき**（`OnExit`） |

> **編集モードで Esc を別扱いにしている理由**: 編集モードには「保存していない変更があります」の確認があるので、
> Esc の処理は [edit_panel.rs](23_edit_panel.md) 側で行います。

> **本番モードを全画面にする理由**: コメントの通り、映る範囲を画面全体にしないと、
> 画面上の大きさと実物の大きさが合わなくなるためです（`BorderlessFullscreen` = 枠なし全画面）。

### `return_home_on_esc`（57〜61行目）

Esc キーが押された瞬間（`just_pressed`）にホームへ戻します。

### `update_camera_layout`（65〜105行目）　★このファイルの中心

毎フレーム、モードとウィンドウの大きさから、2台のカメラの描き方を決めます。

```rust
let (scene_view_layout, main_layout) = match mode.get() {
    AppMode::Home       => (Some(None), None),        // シーンビューだけ全画面
    AppMode::Production => (None, Some(None)),        // メインカメラだけ全画面
    AppMode::Inspection => { ... 左右に分ける ... }
    AppMode::Edit       => { ... UIを除いた範囲にシーンビュー ... }
};
```

戻り値の読み方（`apply_layout` のコメントより）:

| 値 | 意味 |
|---|---|
| `None` | そのカメラは使わない（オフ） |
| `Some(None)` | 画面全体に描く |
| `Some(Some(範囲))` | 指定した範囲に描く |

**検査モード**（81〜92行目）: 左半分にシーンビュー、右半分にメインカメラ。
右側は `fit_aspect` で、**実際のディスプレイと同じ縦横比** の範囲を中央に取ります。

> コメントにある理由: 右半分の縦長の範囲に引き伸ばすと、窓の見え方の計算（非対称視錐台）の比率が実物とずれて、正しい確認にならないためです。

**編集モード**（93〜100行目）: 画面から、右のパネルの幅と上のメニューの高さを引いた範囲にシーンビューを描きます。
メインカメラはオフです（右下の小窓は別のカメラ。[09 camera_preview](09_camera_preview.md)）。

`window.scale_factor()` を掛けているのは、UI の大きさ（論理ピクセル）を画面の実際の画素（物理ピクセル）に直すためです。
Windows の表示スケールが 150% などのときに必要です。

`if size.x == 0 || size.y == 0 { return; }` は、ウィンドウを最小化しているときに何もしないための処理です。

### `apply_layout`（107〜123行目）

計算した結果をカメラに書き込みます。**値が変わったときだけ** 書き込んでいます。

> 毎フレーム同じ値を書くと、Bevy が「変更があった」と判断して余計な処理が走るため、この形にしています。

### `viewport`（125〜131行目）・`fit_aspect`（133〜142行目）

- `viewport` … 位置と大きさから描く範囲を作る（大きさ0にならないよう最低1にする）
- `fit_aspect` … 指定した範囲の中に、指定した縦横比の一番大きい長方形を中央寄せで取る

```rust
if 範囲の縦横比 > 目標の縦横比 {
    高さいっぱい、幅を比率から計算   // 範囲が横長 → 左右に余白
} else {
    幅いっぱい、高さを比率から計算   // 範囲が縦長 → 上下に余白
}
```
