# 12 scene/model.rs　読み込んだモデルの中身を調べる

**一言で**: モデル（.glb/.gltf）の読み込みが終わったときに、中身（peekScreen カメラ、部品、ライト）を調べて記録する。ワールドの部品なら、その部品以外を消す。
**場所**: `src/scene/model.rs`（236行）
**関係するファイル**: [11 scene](11_scene.md)（モデルを出す・置き方を決める）、[23 edit_panel](23_edit_panel.md)（調べた結果を表示）

---

## このファイルの役割

Blender で作ったファイルには、いろいろなものが入っています。

```
room.glb の中身（例）
├ 床          ← 部品
├ 机          ← 部品
│  └ コップ   ← 机の子（机と一緒に動く）
├ ライト      ← 部品（ライトが入っている）
└ peekScreen  ← カメラ。スクリーンの位置を表す（部品にはしない）
```

読み込みが終わったら、これを調べて `ModelInfo` にまとめます。

## 出てくるデータ

### `SCREEN_NODE`（12行目）

```rust
pub const SCREEN_NODE: &str = "peekScreen";
```

Blender でこの名前のカメラを置いておくと、スクリーンをその位置に合わせられます。大文字・小文字も区別します。

### `ModelInfo`（15〜40行目）

| フィールド | 意味 |
|---|---|
| `screen` | peekScreen カメラの位置と向き（ファイルの中の座標）。無ければ `None` |
| `nodes` | 一番上の階層の部品の一覧（名前と Blender での位置）。ワールドとして取り込むとき、これで分ける |
| `part_original` | ワールドの部品なら、その部品の Blender での位置（「Blender の値に戻す」用） |
| `has_lights` | 表示しているものにライトが入っているか |

### `LoadedModels`（43〜70行目）

オブジェクトの id → `ModelInfo` の対応表（リソース）。

| 関数 | 意味 |
|---|---|
| `get(id)` | その id のモデルの情報 |
| `has_lights(layout)` | シーンのどれかにライトが入っているか（入っていればアプリの太陽光を消す） |
| `screen_placement(layout)` | peekScreen カメラの入った最初のモデルの名前と、スクリーンを合わせる位置。編集パネルの「〜の peekScreen カメラに合わせる」ボタンに使う |

`screen_placement` の工夫（59〜69行目）:
- 普通のモデル: モデルを動かしていたら、その分カメラの位置も動かす（`o.placement.to_transform() * screen`）
- ワールドの部品: 部品は Blender の座標のまま置いたものなので、部品を動かしても peekScreen の位置は変えない。名前は部品名ではなくファイル名を出す

### `ModelPart(String)`（79〜80行目）

ワールドの部品として出すモノに貼るシール。中身は表示する部品の名前です。

## 関数ごとの説明

### `on_model_ready`（97〜165行目）　読み込みが終わったとき

[11 scene](11_scene.md) の `spawn_object` で `entity.observe(on_model_ready)` として登録された **オブザーバー** です。
Bevy がモデルの中身を展開し終わったとき（`SceneInstanceReady`）に1回呼ばれます。

```
1. モデルの中を全部たどって調べる（visit）
2. 中に入っていたカメラを全部オフにする
   （ファイルのカメラが、メインカメラやシーンビューと取り合わないように）
3. ModelInfo を作る
4. ワールドの部品（ModelPart あり）なら:
   ├ 指定の部品だけ残す。その部品の位置・回転は消して、大きさだけ残す
   │  （位置・回転はオブジェクトの placement で持つので、二重にならないように）
   ├ ほかの部品とカメラは消す（despawn）
   └ 見つからなければ警告
   普通のモデルなら:
   └ 「◯◯を読み込みました（部品◯個、ライトあり/なし、peekScreen あり/なし）」とログに出す
5. LoadedModels に記録する
```

### `visit`（178〜215行目）　中身を再帰的にたどる

モデルの中の階層（親子関係）を上から順にたどります。自分の子に対して、自分自身をもう一度呼びます（再帰）。

```rust
let global = parent * local;   // 親の位置 × 自分の位置 = ファイル全体の中での位置
```

- 名前が `peekScreen` で、カメラか、カメラを子に持つもの → `found.screen` に位置を記録
  （glTF では、名前の付いたノードの下にカメラが入る形になるため、子も見ている）
- **一番上の階層で、最初に名前が付いているもの** が「部品」
  - カメラを含むもの → 部品にしない（`other_top`）
  - それ以外 → 部品（`top`）
- 一度部品が見つかったら、その下は部品として数えない（`top = false`）。子は親と一緒に動く

### `prune_loaded_models`（218〜222行目）

シーンから消えたオブジェクトの情報を `LoadedModels` から消します（SceneLayout が変わったときだけ）。

### `update_default_light`（225〜236行目）

ライトの入ったモデルがあれば、アプリの太陽光を隠し（`Visibility::Hidden`）、無ければ表示します。
